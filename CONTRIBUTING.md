# Contributing to Shelf

This gets you from a fresh clone to running every part of Shelf and checking your changes. For how the code works, see [docs/](docs/README.md). Commands are one per line, so they work in bash, zsh and fish.

## Prerequisites

- **Rust**, stable, with edition 2024 support ([rustup](https://rustup.rs)).
- **Node.js** 22 or newer and **pnpm** (`npm install -g pnpm`, or Corepack).
- **[buf](https://buf.build/docs/installation)**: generates the TypeScript types from `proto/`. (Rust generates its own at build time; no `protoc` needed.)
- **Tauri CLI** for the app: `cargo install tauri-cli`.
- **Tauri's system libraries** (WebKitGTK and friends) for the Linux app: see [Tauri's prerequisites](https://v2.tauri.app/start/prerequisites/). If a `-sys` crate fails to build, it's usually one of these missing.

Optional:

- **Android**: Android Studio or the command-line SDK with an NDK, and a JDK. `cargo tauri android dev` tells you what's missing.
- **Docker**, to build the server image.

## Get the code

The EPUB renderer, foliate-js, is a git submodule, so clone recursively:

```sh
git clone --recursive https://github.com/psomani16k/shelf.git
cd shelf
pnpm --dir frontend install
```

Already cloned without `--recursive`? Run `git submodule update --init`.

## Run it

Run everything from the repo root unless a step says otherwise.

### Web: server and frontend

The server's library folder is fixed at `/books`, so create it and put a few `.epub` files in it:

```sh
sudo mkdir /books
sudo chown $USER /books
```

Then, in two terminals:

```sh
cargo run -p shelf-server
```

```sh
pnpm --dir frontend dev
```

Open http://localhost:5173. Vite reloads the UI as you edit and forwards `/api` to the server on port 8080. (Opening http://localhost:8080 directly serves the built frontend; run `pnpm --dir frontend build` first.)

### Linux app

```sh
cd app
cargo tauri dev
```

It starts the Vite dev server itself. On first launch, pick any folder of `.epub` files as a local library, or enter `localhost:8080` to use a running server.

### Android app

With a phone connected over USB with USB debugging on (check `adb devices`):

```sh
cd app
cargo tauri android dev
```

A release APK (`cargo tauri android build --apk --target aarch64`) must be signed with your own keystore; see [docs/app.md](docs/app.md#release-signing).

### Server image

```sh
docker build -t shelf .
docker run -p 8080:8080 -v /path/to/books:/books shelf
```

## Before you open a pull request

```sh
cargo fmt
cargo clippy -p app --no-deps -- -D warnings
cargo test --workspace
buf lint
pnpm --dir frontend lint
pnpm --dir frontend test
pnpm --dir frontend exec tsc -b
```

`cargo clippy --workspace -- -D warnings` currently fails on warnings that already exist in `shelf-core`; don't add new ones in the code you touch.

## Where things are

| Path | What |
|---|---|
| `crates/core` | Library logic: scanning, book IDs, EPUB metadata and covers, the `.shelf/` files, the file watcher. No Tauri or HTTP. |
| `crates/utility` | Small shared helpers: time handling and concurrency routines. |
| `crates/proto` | Rust types generated from `proto/`. |
| `crates/server` | `shelf-server`: an axum HTTP server that also serves the built frontend. |
| `app/` | The Tauri app (Tauri's usual `src-tauri`). `app/gen/android` is the Android project. |
| `frontend/` | The React + Vite + TypeScript UI, shared by the web and the app. |
| `proto/` | The schema for every API message and on-disk file. |
| `docs/` | Architecture, on-disk format, API, server, app, frontend, decisions, roadmap, known issues. |

[docs/architecture.md](docs/architecture.md) is the best place to start reading.

## Things to know

- **Every operation goes through one interface.** The `Library` trait in Rust and the `Backend` type in the frontend. An HTTP route and a Tauri command exist for each method, speaking the same JSON. To add one, follow the recipe in [docs/development.md](docs/development.md#add-a-library-operation-end-to-end).
- **Generated code isn't committed.** `frontend/src/gen/` is regenerated by `pnpm dev`, `build` and `test`; the Rust types are generated into `target/`. To change a type, edit the `.proto` file. Never renumber or reuse a field number. Run `buf lint` after.
- **JSON on the wire uses snake_case proto field names** and enum names (`"PAGINATED"`). Protobuf is only the schema, never sent as binary. Details in [docs/api.md](docs/api.md).
- **Don't edit `frontend/vendor/foliate-js`.** It's a pinned upstream submodule.
- **Shelf writes only to `.shelf/` inside a library.** Logs, caches and device settings go in the app's own directories.
- **Rust is async with tokio.** Blocking or CPU-heavy work (ZIP parsing, hashing, image resizing) goes in `tokio::task::spawn_blocking`.
- **Logging uses `tracing` with structured fields**, e.g. `info!(book_id = %id, "progress saved")`. Log an error once, where it leaves Rust, not where it happens. Never log passwords, tokens or auth headers. The frontend logs through `src/lib/log.ts`, not `console.*`.
- **Shared Rust dependency versions** go in the root `Cargo.toml` under `[workspace.dependencies]`.
- **The frontend linter is Oxlint**, not ESLint. UI components come from shadcn/ui: `pnpm dlx shadcn@latest add <name>` from `frontend/`.
- **Few comments.** Prefer readable code; comment only a non-obvious why.

## Docs

`docs/` describes the code as it is, so update the relevant page when you change behaviour. When you build something from [docs/roadmap.md](docs/roadmap.md), tick it off there and describe it in the page it belongs to. If a change goes against a choice in [docs/decisions.md](docs/decisions.md), open an issue to discuss it first.
