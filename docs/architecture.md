# Architecture

## Repository layout

| Path | Crate / package | What it is |
|---|---|---|
| `crates/core` | `shelf-core` | Library logic: scanning, book IDs, EPUB metadata and thumbnails, `.shelf/` files, the watcher. No Tauri, HTTP or prost dependencies. |
| `crates/utility` | `shelf-utility` | Shared helpers with no Shelf types: `timeutil` (clock and `Time`) and `routines` (bounded-concurrency `for_each` / `transform` over a slice, async or `spawn_blocking`). Used by `core` and the app. |
| `crates/proto` | `shelf-proto` | Rust types generated from `proto/` at build time (protox → prost + pbjson). Output goes to `target/`, never committed. |
| `crates/server` | `shelf-server` | axum HTTP server over one `BookLibrary`; embeds `frontend/dist`. |
| `app/` | `app` (lib `app_lib`) | The Tauri 2 app (what Tauri usually calls `src-tauri`). |
| `app/gen/android` | — | Android Gradle project. Generated by `cargo tauri android init` but committed, and edited by hand (plugin, manifest, signing). |
| `frontend/` | `frontend` | React 19 + Vite + TypeScript SPA shared by the web and the app. |
| `frontend/vendor/foliate-js` | — | EPUB renderer, a pinned git submodule. Never edit. |
| `proto/<package>/*.proto` | — | The schema for every wire type and for the on-disk JSON. |
| `Dockerfile`, `docker-compose.yml` | — | Server image and a sample deployment. |

The Cargo workspace (`Cargo.toml`) has members `crates/*` and `app`. Shared dependency versions live in `[workspace.dependencies]`.

## The `Library` trait is the seam

Everything the UI can do to a library is one method on `shelf_core::traits::Library` (`crates/core/src/traits.rs`):

| Method | Returns |
|---|---|
| `list_books(ListBooksRequest)` | `ListBooksResponse` (infallible) |
| `list_sub_directories(ListDirectoriesRequest)` | `ListDirectoriesResponse` (infallible) |
| `get_cover(id)` | `PathBuf` of the thumbnail JPEG |
| `get_book(id)` | `PathBuf` of the EPUB |
| `get_progress` / `set_progress` | progress as an EPUB CFI string |
| `get_state` / `set_state` | the last book opened |
| `get_config` / `set_config(patch)` | library settings; `set_config` merges a partial patch and returns the whole config |
| `rebuild_index()` | `RebuildIndexResponse`: re-hashes every book (ignoring `last_update_time`), reloads the index, returns counts |

Errors are `LibraryError::NotFound` or `LibraryError::Internal(anyhow::Error)`. The methods use `impl Future` in the trait (RPITIT), so the trait isn't dyn-compatible; the app uses an enum (`AnyLibrary`) instead of `Box<dyn Library>`.

Four implementations:

| Type | Where | Backed by |
|---|---|---|
| `BookLibrary` | `crates/core/src/library.rs` | A folder on disk plus its `.shelf/`. Not used directly: the server and the app's local libraries wrap it. |
| `ServerLibrary` | `crates/server/src/library.rs` | Thin wrapper over `BookLibrary` that lets one rebuild run at a time. |
| `LocalLibrary` | `app/src/libsrc/local.rs` | Thin wrapper over `BookLibrary` that lets one rebuild run at a time and remembers a display name. |
| `RemoteLibrary` | `app/src/libsrc/remote.rs` | HTTP calls to a `shelf-server`, with covers and EPUBs cached on disk so it can hand out `PathBuf`s like the local one. |

On the frontend the same surface is the `Backend` type (`frontend/src/api/types.ts`), implemented by `httpBackend` (fetch) and `tauriBackend` (`invoke`). See [frontend.md](frontend.md).

## Request flow in each mode

```
Web
  React ── fetch POST /api/books/list (proto JSON) ──▶ shelf-server (axum)
                                                       └─ BookLibrary ── /books + /books/.shelf

App, local library
  React ── invoke("list_books", { req }) ──▶ app commands ── AppState ── AnyLibrary::Local
                                                                          └─ BookLibrary ── folder + .shelf

App, remote library
  React ── invoke("list_books", { req }) ──▶ app commands ── AppState ── AnyLibrary::Remote
                                                                          └─ reqwest POST {server}/api/books/list
```

The JSON is identical in all three: the frontend encodes the proto message with snake_case field names, and Rust decodes it with pbjson. Covers and EPUB files are the exception: they go as raw bytes (`GET /api/books/{id}/cover|file` over HTTP; an `ArrayBuffer` from `get_cover` / `get_book_file` over IPC).

## Lifecycle of a `BookLibrary`

`BookLibrary::open(root, on_change)` (must run inside tokio):

1. Starts the filesystem watcher (before the sync, so nothing that changes during the sync is missed; its events queue in a channel).
2. Runs the startup sync (`sync_library`, which only hashes new and modified books, one `spawn_blocking` job per book), then loads every `.shelf/books/*/metadata.json` into memory in `spawn_blocking` (`BookKeeper::all_book_metadata`).
3. Deletes temp files left in `.shelf/` by a crash mid-write (`BookKeeper::clean_up_temp_files`). A failure here is logged at `warn` and doesn't stop the library opening.
4. Spawns the extractor task (`receive_and_process_library_updates`, built on `shelf_utility::routines::Debounced`), which drains the watcher channel, debounces each path for 5 s, re-syncs it on the blocking pool, updates the in-memory metadata and calls `on_change`.

`rebuild_index` runs the same sync with `force` (every book hashed and re-extracted) and swaps in the reloaded metadata. `BookLibrary` doesn't stop two rebuilds running at once; its wrappers (`ServerLibrary`, `LocalLibrary`) each hold a `rebuild_lock`, so a second rebuild waits for the first. `RemoteLibrary` has none, since the server's lock covers it. Dropping the `BookLibrary` drops the watcher, which closes the channel and ends the extractor task. Details in [library-format.md](library-format.md).

`on_change` is a no-op in the server. In the app it emits the `library-changed` Tauri event, and the frontend refetches its folder listings.

## Shared conventions

- **Proto is the schema, JSON is the wire.** Never binary protobuf. See [api.md](api.md).
- **The frontend never sees file paths**, only book IDs. (The app's library picker is the one exception: it passes a chosen folder path *to* Rust.)
- **tokio everywhere**; blocking or CPU-heavy work goes in `spawn_blocking`, with `shelf_utility::routines` bounding how many jobs run at once (see [known-issues.md](known-issues.md) for the blocking `std::fs` exception).
- **Errors are logged once**, where they cross the boundary: `crates/server/src/error.rs` for HTTP, `app/src/error.rs` for Tauri commands.
