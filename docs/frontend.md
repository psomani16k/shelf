# Frontend

`frontend/` is one React SPA used by both the web build (served by `shelf-server`) and the Tauri app.

Stack: React 19, Vite 8, TypeScript 6, Tailwind CSS v4, shadcn/ui on Base UI (Nova preset), TanStack Query v5, React Router v8, protobuf-es v2, lucide icons, foliate-js for rendering EPUBs.

## Generated proto code

`pnpm gen:proto` runs `buf generate` from the repo root with `protoc-gen-es` (`buf.gen.yaml`, `target=js+dts`) into `src/gen/`. `dev`, `build` and `test` run it first. JS + `.d.ts` rather than TS because protobuf-es emits TS `enum`s, which `erasableSyntaxOnly` rejects. Messages are used as `create(Schema, init)`, `toJson`, `fromJson`; enum values as `ReaderFlow_Value.PAGINATED`.

## The backend layer (`src/api`)

| File | What |
|---|---|
| `types.ts` | `Backend`: `listBooks`, `listDirectories`, `getProgress`, `setProgress`, `getState`, `setState`, `getConfig`, `setConfig`, `listThemes`, `setTheme`, `deleteTheme`, `renameTheme`, `exportUserData`, `importUserData`, `rebuildIndex`, `cleanUpProgress`, `getCover`, `getBookFile`, `uploadBook`, `createDirectory`, `deleteItems`, `login`, `logout`, `me`, `changePassword`, `signUp`, `listUserRequests`, `approveUserRequest`, `denyUserRequest`, `listUsers`, `setUserRole`, `setUserScope`, `listScopeDirectories`, `listSessions`, `signOutSession` |
| `http.ts` | `httpBackend`: `fetch` to same-origin `/api`, `login` sending the browser's name from `lib/deviceName.ts` ("Firefox on Linux", worked out from the user agent here so the server never sees it parsed or kept), with `Authorization: Bearer` from `session.ts` on every request (the upload's XHR too). | `proto.ts` | `encode(schema, init)` (`toJson` with `useProtoFieldName`, so keys are snake_case) and `decode(schema, json)` (`fromJson` with `ignoreUnknownFields`), used by both backends |
| `tauri.ts` | `tauriBackend`: the same calls over `invoke` (`exec` for commands with no answer, `query` for those with no arguments). `uploadBook` sends 2 MiB base64 chunks (`FileReader.readAsDataURL`) and reports progress after each. | `index.ts` | Picks `tauriBackend` or `httpBackend` by `IS_TAURI` and exports each of its functions by name |
| `error.ts` | `ApiError(status, message)`, thrown by both backends |
| `app.ts` | App-only commands: library list management, `listLocalUsers`, the interface scale (`uiScale`, `setUiScale`), `setKeepScreenOn`, log settings and export, `saveJsonFile` (the data export's save picker), storage permission, folder picker, insets, `onLibraryChanged` |

Components import from `@/api` and don't know which backend they're on. App-only code imports from `@/api/app`.

`getCover` and `getBookFile` return `Blob`s in both backends.

## Signing in (`src/lib/session.ts`, `src/lib/useMe.ts`)

- **Web:** the token from `login` is kept in `localStorage["shelf.token"]`, so the browser stays signed in (90 days from the last use). Reads and writes are wrapped in `try`: without storage the session lasts until the page reloads.
- **Signed out** is one flag with subscribers (`useSignedOut`, a `useSyncExternalStore`). It starts true on the web when there's no token. Any 401 (except from `login` itself) sets it, and so does `logout`; `login` clears it. In the app, `resetLibraryCache` (switching or adding a library) clears it too, and whether the open remote library needs a login comes from its `signed_in`.
- **`useMe`** (`["me"]`) is the signed-in user, or `null` for a local library. `permissions(user)` gives `canAdd` (`CONTRIBUTOR` and up), `canDelete` (`LIBRARIAN` and up) and `canAdmin` (`ADMIN` and up); `null` (a local library) allows everything but `canManageUsers`, and nothing is allowed while it loads. The server enforces the same rules, so hiding is only for tidiness.

## Platform flags (`src/lib/platform.ts`)

```ts
export const IS_TAURI = isTauri()                                         // inside the app
export const IS_ANDROID = IS_TAURI && /android/i.test(navigator.userAgent)
```

Evaluated once at load. This is the switch for app-specific behaviour. Current uses: backend choice, the router, `AppFlow` and `WebFlow`, where the login token lives, system insets, the library switcher in the library slideover, the library list in Settings → Library, the interface scale (Settings → Interface and the reader), the *Developer options* settings section, forwarding logs to Rust, the folder picker, the storage-permission step and the back button on Android (whose log-folder line is hidden), when `Login` clears the cache (before the request on the web, `resetLibraryCache` after it in the app), *Account*'s "other devices and browsers" wording, and how *Library* saves a data export (`saveJsonFile` in the app, a download on the web) and whether it says to ask an admin.

## App flow (`App.tsx`, app only)

1. `useSystemInsets()` publishes system bar sizes as CSS variables.
2. Subscribes to `library-changed` → invalidates `["dirs"]` and `["books"]`.
3. `useLibraries()` (`list_libraries`) and `useCurrentLibrary()`: the stored `current` if it's still in the list, else the first library. Pending → spinner; error → `OpenFailed`; no library → `PickLibrary`.
4. Opens the current library with a query keyed by `["open-library", name]` (`staleTime`/`gcTime: Infinity`, no retry). Pending → `Syncing`; error → `OpenFailed` (*Try again*, *Remove this library*, or switch to another).
5. `<MemoryRouter key={name}><Home/></MemoryRouter>`: in memory and keyed, so each library starts at `/` and no URL or folder survives a switch.

### Libraries (`lib/useAppLibrary.ts`)

- **Add** (`AddLibraryForm`: name, then a folder or a server URL; used by `PickLibrary` on first run and by Settings → Library → *Add library*). The name is required and checked against the list (ignoring case) before Rust checks it again. Choosing a folder or leaving the URL field pre-fills an empty name with the folder name or host. Adding switches to the new library.
- **Switch** (`LibrarySwitcher`, in its own strip just above the library slideover's bottom bar (settings gear), opening upward; also on `OpenFailed`): each entry shows the name and its source (folder path or server URL).
- **Remove** (red icon per row in Settings → Library, or *Remove this library* on `OpenFailed`): an inline `RemoveLibraryConfirm` explains that nothing in the library is deleted.

Switching, adding, and removing the open library all call `resetLibraryCache` (and switching reader `resetUserCache`; both share one `resetCache`, with the keys each keeps marked in `queryKeys.ts`): it removes **every cached query except `["libraries"]` and the interface scale** (books, folders, last book, covers, the open-book file, `["library-config"]` and `["themes"]`), drops uploads that haven't started, then refetches the list. `AppFlow` then opens the new current library, and Home remounts and loads that library's own data and **config** (theme, layout, margins). Removing a library that isn't open only refetches the list.

## Home and reading

- **State**: `["state"]` → `getState`. `lastBookId` is the open book. Picking a book calls `setState` and writes the result into the cache.
- **Library drawer** (left): `LibraryPanel` with queries `["dirs", folder]` and `["books", folder]`. The current folder is in memory only. Its bottom bar has Settings on the left and, on the right:
  - **Select:** selection mode, also started by a long press on a folder row or book tile on touch screens (`lib/useLongPress.ts`: 500 ms held within 10px; the click that ends it and Android's long-press menu are swallowed). Rows and tiles show a check mark and a tap toggles them (books are selected by file name, so two copies of one book in a folder are separate tiles); the bar becomes cancel, "N selected", *Select all* / *Select none* and delete. Delete asks first, inline in the bar ("Folders are deleted with everything in them. This can't be undone."), then calls `deleteItems` with each ticked copy (`books`: id, folder and file name, so other copies of the book stay) and invalidates `["books"]`, `["dirs"]` and `["state"]`, so a deleted open book closes (`Home` then shows its title as "Shelf"). Changing folder ends selection.
  - **New folder:** the bar becomes a name field with *Create*; errors such as a taken name show under it. Success invalidates `["dirs", folder]`.
  - **Upload:** a hidden `<input type="file" multiple accept=".epub,…">`. Picked files go to `uploads` (`lib/uploads.ts`), a store outside React read with `useSyncExternalStore`, so uploads carry on with the drawer closed. It uploads one file at a time; a failure (a 409 for a taken name, a 400 for an unreadable EPUB) marks that file and the rest carry on. Each success invalidates `["books", <its folder>]`. Switching library drops the files still waiting (`resetLibraryCache`), since they'd go to the new library.
- **Contents and highlights drawer** (right): only when a book is open. `BookPanel` has two tabs, *Contents* (`TocPanel`) and *Highlights* (`HighlightsPanel`); `Home` keeps the tab while the book is open.
- **Reader**: query `["open-book", id]` loads the file and the saved progress together (progress is read once, when the book opens; nothing refetches it while reading). foliate's `View` opens a `File` (it needs a name ending in `.epub`), then `init({ lastLocation: cfi, showTextStart: true })`.
- **Progress**: `progressSaver` saves the CFI 2 s after page turns stop, and flushes immediately on `pagehide`, when the page becomes hidden, and on unmount. On the web the flush uses `fetch(..., { keepalive: true })` so it survives the tab closing; IPC has no equivalent and ignores it.
- **Input**: paginated — foliate handles swipes; ← → and the buttons turn pages. Scrolled — native scroll with a 3px section line under the header instead of a scrollbar; a one-finger horizontal swipe (not while pinch-zoomed), horizontal wheel, ← → or the buttons change section. Keys, swipes and the wheel are ignored while a drawer or settings is open. **Pinch zoom** (`lib/pinchZoom.ts`, Android app only) works only on the reader, while no drawer, settings or *Aa* drawer is open: `main.tsx` turns it off in the viewport meta (`maximum-scale=1, user-scalable=no`), and `Reader`'s `usePinchZoom` turns it back on, so leaving the book snaps a zoomed page back to 1×. The web keeps pinch zoom everywhere, for accessibility. Buttons float at the sides for mouse users and are always in the bottom bar.
- **Bars**: the header (`SlideDrawer`'s `header`, which covers the top of the page) and the reader's bottom bar (the 3px book line along its top edge, then ‹, the current chapter, % through the book, the *Aa* button, ›) float over the book, so showing or hiding them never re-lays it out. `Home` holds whether they show (`bars`), starting shown and reset when another book opens. The header hides only while a book is open. Reading hides them: a touch that moves 10px or more, the wheel in scrolled mode, a reading key (arrows, Page Up/Down, Space) outside a control and an open dropdown list, or a floating button. A tap or click on the page (not on a link, not ending a text selection) toggles them. The bar's own buttons leave them up. While hidden, the 3px lines stay at the edges: the section line moves from under the header to the top edge, the book line to the bottom edge; the book's padding keeps text clear of them. The lines use the UI's background and foreground colours, so they show whatever the reader's colours.
- **Quick settings** (`ReaderQuickSettings.tsx`): the bar's *Aa* button opens a drawer from the bottom (`ui/drawer.tsx`, Base UI's Drawer: swipe down, tap outside, Escape or Android back closes it) with zoom, *Theme*, *Layout* and *Images*, and *More settings*, which opens Settings → Reader over the book (`state: { depth: 1 }`, so closing it comes back). Theme, Layout and Images are the same controls as Settings → Reader (`ThemeSelect`, and `READER_FLOW` and `READER_IMAGES` in `sections.ts`), saved to the user's config with `useSetConfig` (`lib/useAppearance.ts`): a new theme recolours the page above the drawer, a new layout re-lays the book out, and *Images* recolours its pictures. Its backdrop is clear and unblurred so those changes show, and it catches taps on the book, so they close the drawer instead of turning pages; while it's open the reader is paused (`Reader` owns the open state). Keys inside an open dropdown's list (`role="listbox"`) are left to it.
- **Reader theme** (`lib/readerTheme.ts`, `lib/colorMatrix.ts`): the book is always drawn as published, and the chosen theme (`useReaderLook()` in `lib/useAppearance.ts`, passed to `Reader` from `Home`) recolours it. `themeLook` composes the theme's layers into one colour matrix (each layer's matrix is the CSS Filter Effects one: `invert`, `hueRotate`, `saturate`, `brightness`, `contrast`; `levels` and `multiply` per channel; or the raw 12 values). A layer with no kind or bad values is skipped, and negative factors count as 0. The page colour is white through the matrix; the floating buttons' scheme comes from its luminance. `applyLook` puts the matrix as an SVG `feColorMatrix` into each section's own document (`url(#…)` can't reach across documents) and sets `--shelf-filter` and `--shelf-image-filter` on its `<html>`, which `readerCss` uses to filter `<body>` and its images. `readerCss` also sets `hyphens: auto` on `<body>` (not `!important`, so a book that turns hyphenation off keeps it off), which closes the gaps in justified text on phones. Each page's `<html>` is transparent, and the page colour is the reader's wrapper behind the iframes: foliate copies a page's background into its own layer only when it loads or its styles are set, so a page colour there went stale after a switch (overscroll showed the old one). The wrapper is `color-scheme: light` like the pages, since browsers paint an iframe opaque when its scheme differs from its embedder's. So switching themes changes two variables on each loaded page (`renderer.getContents()`, plus the `load` listener for later ones) and never lays the book out again. Filter ids are a hash of the values, because WebKitGTK keeps using a resolved filter after its values change. Filtering `<foliate-view>` instead broke in WebKitGTK's scrolled mode. With *Images: Keep colours*, images get `M⁻¹ · M_img` first (M_img is the layers not marked `skip_images`), so the two together give them only those layers; with *Like the page*, or when the matrix has no inverse, they get the whole theme.
- **Highlights** (`lib/highlights.ts`, `lib/useHighlights.ts`, `Reader.tsx`). There are no bookmarks: every highlight can be jumped to from the list.
  - **Data:** query `["annotations", id]` → `listAnnotations`, apart from `["open-book", id]` so an unreadable highlights file (a 500) never keeps the book from opening; the toolbar then doesn't open, and the tab shows the error with *Try again*. `useAddHighlight`, `useUpdateHighlight` and `useDeleteHighlight` write the backend's answer into that cache; the reader and the list both draw from it, so a change in either shows in both. Ids come from the backend, so nothing is drawn before it answers.
  - **Drawing:** through foliate's overlayer, which sits outside each section's iframe, so the theme filter never recolours highlights. foliate keys drawn annotations by `value`, the highlight's CFI. `create-overlay` (a section loaded) draws that section's highlights (sections found with `resolveCFI`, cached per CFI); `draw-annotation` draws one with `drawHighlight` (`Overlayer.highlight` plus a dot at the end when it has a note) in its colour's shade for the theme's scheme. An effect diffs the cache against what was drawn: gone ones are deleted, new ones or ones whose colour or note changed are drawn again, and all are redrawn when the scheme changes. Colours are names; each has a `swatch` for the UI and a `page` shade per scheme, mixed by `--overlayer-highlight-blend-mode` and `-opacity` on `<foliate-view>` (`highlightStyle`): `multiply` on light pages (dark text stays dark), `lighten` on dark ones (light text stays light).
  - **Selecting:** each section's `selectionchange`, settled for 300 ms (Android's handles fire it constantly while dragged), or a mouse's `pointerup`, opens `HighlightToolbar` by the selection: the CFI from `getCFI`, the chapter from `getProgressOf`, and the text as one line, all clamped to the backend's limits in characters. A colour adds the highlight and clears the selection; *Note* adds it in the last colour used this session (yellow at first) and opens the note editor; *Copy* copies (`copyText`: Rust's clipboard in the app, `navigator.clipboard` on the web). A selection that is exactly an existing highlight opens that highlight's toolbar instead.
  - **Tapping a highlight** (`show-annotation`) opens its toolbar: colours (the current one ringed), note, copy and delete. Delete is immediate unless there's a note, which asks inline first. The trap: the paginator fires `load`, where the reader adds its tap listener, before foliate adds its hit test, so the reader's tap runs first; it toggles the bars (or closes an open toolbar) in a `setTimeout(…, 0)` that `show-annotation` cancels. Not a microtask, which would run between the two listeners.
  - **The toolbar** is placed from the range's rect plus its iframe's, above the selection or below it when the header is in the way, clamped inside the page (`placeToolbar`), and again on `relocate` and scroll, set straight on its style so scrolling doesn't re-render. A tapped highlight's toolbar closes when the page turns; a selection's waits. Escape, a tap elsewhere, or a drawer or settings opening closes it. Its buttons `preventDefault` on `pointerdown`, so the selection survives.
  - **Android:** the WebView's floating Copy/Share bar would sit over the toolbar, so while the reader isn't paused it calls `set_selection_menu(false)`. `MainActivity.onWindowStartingActionMode` then answers a floating action mode with `SilentActionMode`, which shows nothing while the selection and its handles keep working. It goes back on (`true`) whenever a drawer or settings is open, since those have text fields that need Copy and Paste, and when the reader unmounts. The flag follows the UI, not each selection, so there's no race with the long-press.
  - **List:** grouped by chapter in reading order (`byPosition`, foliate's `CFI.compare`), each entry with its colour's bar, the text (3 lines), the note (4 lines) and the date. A tap jumps there and closes the drawer; `⋯` opens a row of colours, *Add/Edit note*, copy and delete. *All · With notes* chips show only when some have notes and some don't.
  - **Note editor:** inside the *Highlights* tab rather than a bottom sheet, so Android's keyboard can't cover the field: the quoted text, a textarea (focused without scrolling the drawer), *Cancel* and *Save* (an all-blank note is saved as none). The reader's *Note* opens the drawer on it; closing the drawer, Android back or *Cancel* leaves it.
- **Dictionary** (`components/DefinitionSheet.tsx`, `lib/dictionary.ts`, `lib/wikiHtml.ts`): frontend only, from Wiktionary's REST API. For a selection or highlight of 1–3 words and at most 64 characters (`isDefinable`), the toolbar shows **Define**, which clears the selection and opens a bottom sheet (`ui/drawer.tsx`) with the word as typed-over text (`normalizeTerm`: no surrounding punctuation, straight apostrophes).
  - **Lookup:** `useDefinition(term)`, query `["definition", term]`, fetched once per session. Titles are case-sensitive, so `fetchDefinitions` tries the word as selected, then lowercased; a 404 for both is "no entry", which offers *Search web*. Entries are grouped by language, the book's own (`metadata.language`) first, then English, then the rest by name; empty definitions are dropped.
  - **Safety:** definitions are HTML. `parseWikiHtml` parses it into an inert document (`DOMParser`: no scripts run, nothing loads) and keeps only text, bold, italic, lists (sub-senses) and links to other entries (`mw:WikiLink` without a `:` namespace), which the sheet renders as React elements, never as HTML.
  - **The sheet:** the word is an editable field (Enter or the search icon looks it up and closes the keyboard); a linked word is looked up in place. Both push onto a history that the back arrow and Android back pop, then close. It's a fixed 70% of the screen high, so the field near its top stays above Android's keyboard; it isn't focused on open. While it's open the reader counts as paused, and Android's own selection menu is back for the field's Paste. The footer has *Search web* and the credit the licence asks for ("From Wiktionary · CC BY-SA 4.0", opening the entry).
- **Search web** (`lib/webSearch.ts`, `lib/external.ts`): the toolbar's globe (any selection, cut to 500 characters) and the dictionary's button open the user's search engine (*Settings → Reader → Search web*, `reader.search_engine`: DuckDuckGo by default, Google, Bing, Startpage or Ecosia) in the default browser: `openUrl` from `tauri-plugin-opener` in the app, a new tab on the web.
- **Zoom** (`lib/readerZoom.ts`): −, the level, + and reset, stepping 10% at a time from 50% to 200% (`ZOOM_STEPS`, derived from the interface scale's `UI_SCALE_CHOICES`). A level saved under older steps snaps to the nearest one (`snapZoom`). It's per device, like browser zoom, so it's kept in `localStorage` (`shelf.reader-zoom`, falling back to 100% when storage is blocked) rather than the library's config. `readerCss` sets CSS `zoom` on each page's `<body>` (not `<html>`, whose columns foliate sizes in px), so text and spacing scale and the book re-lays out. The zoom applied is the interface scale times this level, rounded to a hundredth, so the drawer's % is relative to the interface. Images, videos and top-level SVGs get the inverse zoom, because foliate caps their height to the page in px and a zoomed body would push them past it: they keep their size, fitted to the page.
- **Settings** is a route (`/settings/:section?/:page?`) rendered over Home, which stays mounted (`inert`) behind it. Escape closes it, unless an open select took the Escape.

## Settings and appearance

- `["library-config"]` → `getConfig`, read once; `setConfig` results are written straight into that cache.
- `["themes"]` → `listThemes` (`useReaderThemes`), read once; the theme calls answer with the new list. `useReaderTheme` picks the entry whose id is the config's `reader.theme`, else the list's `default_id`. The frontend knows no theme by name: the built-ins come from the backend. `useSaveTheme` and `useDeleteTheme` write their answers into the same cache. `renameTheme` is in `Backend` but nothing calls it yet.
- **Theme builder** (`ThemeBuilder.tsx`):
  - **Preview:** an `<iframe srcdoc>` of a sample page (`lib/themePreview.ts`: headings, a link, italic and bold, red and green text, a highlight, a blockquote, a syntax-coloured Rust snippet, colour chips, and two real photos in `src/assets/theme-preview/` (a dark sunset and a brightly coloured market stall) as `<img>`, so the image filter applies). It has the reader's own `readerCss()`, and `applyLook` themes it on load and on every change, the same path as a book's pages, inside a `color-scheme: light` iframe over the look's page colour. It sticks to the top while the layers scroll. Its *Images* toggle starts from the user's setting and changes only the preview.
  - **Name:** always empty, even after *Start from*, and needed to save. Checked as it's typed with `themeId` (`lib/readerTheme.ts`, the backend's rule). A name whose id is one of the user's themes says it replaces it; a built-in's says it replaces it until yours is deleted; either way *Save theme* first asks *Replace "X"?*.
  - **Start from:** copies a theme's layers (`copyLayer`, a deep clone, so the cached theme is never changed); *Book as published* empties them.
  - **Layers**, applied top down (`lib/themeLayers.ts`: `LAYER_LABELS`, `newLayer`, `moveItem`, `MAX_LAYERS` = 32): each with move up / down, delete, a *Leave images out* switch (`skip_images`) and its controls: sliders for hue (−180…180°), saturation (0…3), brightness and contrast (0…2); colour pickers plus a hex field for Levels and Multiply; a 3 × 4 grid of numbers for the matrix (text fields that keep what's typed and pass on only finite numbers). New layers change nothing, except Invert, which also starts with *Leave images out* on. A layer a newer Shelf added shows as *Unknown layer* and blocks saving until it's deleted. *Add a layer…* is a select of kinds.
  - **Saving** (`useSaveTheme`) doesn't pick the theme; it goes back to *Themes*. The server's 400s show above the button.
- `resolveAppearance` (`lib/appearance.ts`) turns `Config` into concrete values; unset fields mean the proto zero value. `useAppearance` also toggles the `dark` class on `<html>`.
- `components/settings/sections.ts` defines sections. A section can have `pages` (`/settings/<section>/<page>`, each with a title, a component and a `parent` page; today Reader's `themes` and `new-theme`): a page replaces the section's content and title, its back arrow and the Android back button go up one level, and an unknown page redirects to its section. A section has `groups` of `Setting`s (each bound to a `Config` field via `read`/`patch`, shown as a `ChoiceRow`) and `CustomSetting`s (a component given `save`, for choices that aren't fixed, like *Theme*), a `content` component for settings that aren't in the library config, or both (`content` renders after the groups). *Library* (`LibrarySection.tsx`) is shown everywhere: *Rebuild index* (on success it invalidates `["dirs"]`, `["books"]` and `["state"]`, since IDs can change) and *Clean up progress* (*Clean up* swaps the row's text for "Delete it? This can't be undone." with *Cancel* and a red *Delete*, then shows how many books' progress and highlights were removed; nothing to invalidate, since removed books aren't listed), both for admins and up and anyone with a local library, and, only when `IS_TAURI`, the list of libraries (red remove icon per row, *Add library* at the bottom). App-only settings go behind `IS_TAURI` inside a section's component, with their hooks in a separate component so the web never calls app commands.
- A section marked `appOnly` (today *Developer options*, slug `developer`, `CodeXml` icon) is left out on the web, so it never shows or calls its commands. One marked `adminOnly` (today *Admin*, slug `admin`, `ShieldCheck` icon) shows only to a remote library's admins and owners (`canManageUsers`). `useVisibleSections()` applies both, and `Settings.tsx` renders what it returns. While `me` is still loading, *Admin* is hidden from the list, and `Settings.tsx` renders nothing for an unknown slug instead of redirecting to the list, so a reload on `/settings/admin` opens it once the role arrives.
- *Developer options* (`LogsSection.tsx`), under a *Logs* heading: *Log files to keep*, a number field (1 to `max_keep_files`) saved on Enter or when the field loses focus, with an inline error for anything else (query `["log-settings"]`); *Copy logs* and *Save logs…*; and *Files*, every log file newest first (query `["log-files"]`, refetched after the count changes), shown by the time span it covers (start to last write) and its size, with the file name small underneath, a save button per row (`save_log_file`), and the folder on desktop. The count is stored on the device, not in the library config.
- **Keep screen on** (`lib/keepScreenOn.ts`, app only): Settings → Interface → *This device* → *Keep screen on*, on by default, kept in `localStorage` (`shelf.keep-screen-on`) since it's per device. While the reader isn't paused (no drawer or settings open), `useKeepScreenOn` calls `set_keep_screen_on(true)`; every page turn (`relocate`), tap and key in the reader restarts a 10-minute timer (`IDLE_MS`), after which it sends `false`, so a book left open still lets the screen sleep. Hiding the app, pausing or closing the reader sends `false` at once; it only sends when the state changes.
- **Interface scale** (`lib/uiScale.ts`, app only): Settings → Interface → *This device* → *Scale*, 50–200% in 10% steps (`InterfaceSection.tsx`). It's stored in the app data on the device (`ui_scale` / `set_ui_scale`), not in the library config. It sets the root font size (`<html style="font-size: 120%">`). Tailwind and shadcn size in rem, so the whole UI scales, while px borders, the 3px lines, the `--inset-*` safe-area padding and viewport units don't. CSS `zoom` on the root would scale viewport units too, and Tauri's webview zoom doesn't work on Android. `main.tsx` awaits `loadUiScale` before the first render, so nothing paints at 100% first, and seeds `["ui-scale"]`, which a library switch keeps. `useUiScale()` gives the factor (1 on the web). The reader multiplies its zoom by it and widens the floating buttons' text inset (`BUTTON_INSET`) to match.
- These settings are the user's own, stored in the library (`.shelf/users/<user>/config.json`), so they follow that user to every device using the library, and each user, readers included, has their own. The `["library-config"]` cache is dropped on a library switch, so the new library's settings load fresh.

## Logging (`lib/log.ts`)

- `log.debug/info/warn/error(message, fields?)` always writes to the console. In the app, it also sends `message key=value …` to Rust through `@tauri-apps/plugin-log`, which lands in the app's log files. Forwarding failures are swallowed, so logging never throws. Never pass secrets.
- `installErrorHandlers()` (called in `main.tsx`) forwards uncaught `error` and `unhandledrejection` events, with the stack. It doesn't log them to the console again, since the browser already does.
- Use `log` instead of `console.*` for anything worth keeping.

## Covers

`useCover(id)` (`lib/useCover.ts`) fetches the cover blob via `getCover` into query `["cover", id]` as an object URL (`staleTime: Infinity`, no retry; an error means "no cover", shown as an icon). `revokeCoversOnRemoval` (called in `main.tsx`) revokes the object URL when the query cache drops the entry, so blobs don't leak.

## Safe area (Android system bars)

The Android app draws edge to edge, so the page needs padding for the status bar, navigation bar and cutout:

- `index.css` defines `--inset-top/right/bottom/left` (default `0px`) and a Tailwind utility `safe-area` that pads by them.
- `useSystemInsets` (app only) sets those variables on `<html>` from the `system_insets` command on mount and on every `resize` (covers rotation).
- `safe-area` is applied to every full-screen surface: `SlideDrawer`'s root (with an inner `relative size-full` box so its absolutely positioned children respect the padding), the `Settings` root, and `CenteredScreen`. **Any new full-screen or `fixed inset-0` surface needs it too.**

On the web and desktop the variables stay `0px`.

## Android back button (`lib/backButton.ts`)

The app uses a `MemoryRouter`, so the WebView has no history of its own. Instead, each open layer registers a handler with `useBackButton(onBack, active)`, and back runs the newest one:

- An open drawer (`SlideDrawer`) closes.
- Settings (`Settings.tsx`) does what its header arrow does: a section on a phone goes back to the list; otherwise settings closes.

Tauri's `onBackButtonPress` takes the button over completely, so the listener is registered only while at least one layer is open and removed when the last one closes. With nothing open, Android's own behaviour applies (the app goes to the background). Opening settings from the library drawer stacks settings on top, so back closes settings and then the drawer. Pop-ups such as an open select aren't layers: back closes the screen under them. The permission comes with `core:default`.
